# Incident Response

Severity 1: confirmed cross-tenant access, secret compromise, material data loss, payment integrity failure or total outage. Severity 2: major degraded function without workaround. Severity 3: limited defect.

Detect and assign an incident lead; preserve evidence; contain using key/session revocation, provider secret rotation, deployment rollback or controlled write freeze; communicate factual status; eradicate root cause; validate tenant isolation, reconciliation and dependencies; recover through preview acceptance and monitored promotion; notify affected parties/legal counsel where required; write a blameless postmortem with timeline, impact, cause, controls and owners. Never destroy logs or rotate a credential without recording scope and time.
